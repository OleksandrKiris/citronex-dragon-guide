## Польза и воспроизведение

В общем вступлении (?lang=en&welcome=1, без location) после MediaError
повтор оставлял тот же src и пропускал audio.load(). Неисправный медиаресурс
не проходил новый цикл загрузки. Девять регрессионных случаев на коде базы
падали: loads=1 вместо2. Это Node/VM-модель media lifecycle, не реальное
отключение сети и не браузерное воспроизведение.

Исправлена одна проверка: совпадающий src сохраняется без перезагрузки,
только если audio.error отсутствует. При ошибке явные Start/Replay запускают
новую загрузку того же MP3. Событие error само ничего не скачивает повторно.
Здоровый повтор использует прежний буфер. При повторном отказе остаются
существующие текст, сообщение и переход дальше; бесконечных повторов нет.

Озвучка, тексты/переводы, контакты, маршруты, speech synthesis и правила
переходов не менялись. Подпись PR7 сохранена. Новые строки интерфейса,
хранилища, миграции, API и зависимости не добавлены. Девять языков и ka→en
с пояснением остаются прежними. Сохранённые язык/seen и посторонние ключи
не удаляются; новый код не записывает прогресс/персональные данные.

## Первый запуск / офлайн

Для локальной проверки полного checkout: python3 -m http.server 8080
--bind 127.0.0.1, затем http://127.0.0.1:8080/?lang=en&welcome=1 .
Остановка Ctrl+C. Этот способ документирован, но здесь браузером не проверен.
Service worker через file:// не обещается. Первый запуск PWA требует сети;
офлайн возможны только успешно загруженные и сохранённые ресурсы. Аудио
запрашивается по действию, не при открытии. После смены cache старые аудио
могут потребовать повторной онлайн-загрузки: сохранность офлайн-аудио при
обновлении не обещается. Голоса ОС и внешние учебные страницы имеют собственные
условия доступности. При недоступном аудио остаётся текст; исправление не
добавляет офлайн-контент и не гарантирует восстановление без сети.
